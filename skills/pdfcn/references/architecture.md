# Architecture

pdfcn is a pnpm + Turborepo monorepo with a single app, `apps/web`, which is both the product
(the registry source) and its documentation site. `pnpm-workspace.yaml` also globs `packages/*`,
but no packages exist today.

## Repository root

| Path                                  | Role                                                                                                        |
| ------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `package.json`                        | Root scripts that fan out through Turbo to `apps/web` (see [commands.md](commands.md)); pins `pnpm@10.28.2` |
| `turbo.json`                          | Task graph: `build`, `typecheck`, `dev`, `start`, `registry:build` (uncached)                               |
| `lefthook.yml`                        | Pre-commit hook: `pnpm fix {staged_files}` on `js/jsx/ts/tsx/json/jsonc/css`, re-stages fixes               |
| `oxlint.config.ts`, `oxfmt.config.ts` | Ultracite lint and format config; both ignore `.agents/**`, `.cursor/**`, `apps/web/public/r/**`            |
| `skills/`                             | Skills this repo publishes (this skill lives in `skills/pdfcn/`)                                            |
| `.agents/skills/`, `skills-lock.json` | Third-party skills installed for contributors (for example `launch-shadcn-registry`)                        |
| `.github/`                            | CI (`workflows/ci.yml`), DCO config, PR template, issue templates                                           |
| `CONTRIBUTING.md`                     | Human contribution guide; [contributing.md](contributing.md) is the agent-facing version                    |

## `apps/web`

A Next.js 16 App Router app. Docs are MDX rendered by fumadocs (`source.config.ts`,
`mdx-components.tsx`). Internationalisation with Intlayer is proposed in PR #8 and is not on
`main`.

```
apps/web/
├── registry.json                 # shadcn registry index (the source of every published item)
├── registry/                     # the product
│   ├── bases.ts                  # BASES list: name, title, dependencies, logo per base
│   ├── config.ts                 # zod schema for { base, theme } with defaults
│   ├── themes.ts                 # theme presets map + re-exported theme types
│   ├── themes/<name>.ts          # professional, modern, minimal, … and primitives.ts
│   ├── types/                    # pdf-components.ts (Style, PDFComponentProps), pdf-themes.ts
│   └── bases/<base>/
│       ├── registry.ts           # { name, sourceDir, examplesDir }
│       ├── lib/                  # pdf-primitives.tsx, pdf-svg.tsx, resolve-color.ts (+ forme maybe-fixed.tsx)
│       ├── components/<name>/    # building blocks: text, table, section, page-header, …
│       │   └── theme-provider.tsx
│       └── blocks/<name>/        # full documents: invoices, reports, forms, …
├── public/r/                     # generated by `shadcn build`; committed
│   ├── registry.json             # public index
│   ├── takumi/<name>.json        # one file per item, sources inlined
│   └── forme/<name>.json
├── examples/
│   ├── <base>/<name>.tsx         # preview demo per item (default export, no props)
│   ├── __index__.ts              # demos map: { takumi: {...}, forme: {...} }
│   ├── preview-config.tsx        # Takumi preview page margins and sizes (BLOCK_NAMES, COMPONENT_SIZES)
│   └── preview-assets.ts         # Forme preview image source replacement
├── app/api/pdf/<base>/route.tsx  # GET ?name=<demo> → PDF; &format=document → JSON tree
├── content/docs/
│   ├── (root)/                   # index, installation, registry, mcp, changelog
│   ├── components/<base>/        # one MDX page per component + meta.json (sidebar order)
│   ├── blocks/<base>/            # one MDX page per block + meta.json
│   ├── themes/, theming/<base>/
├── components/                   # site UI: component-preview, component-source, web-mcp tools
└── mdx-components.tsx            # MDX component map (ComponentPreview, ComponentSource, CodeTabs, …)
```

## How the pieces connect

```
registry/bases/<base>/…  ──(registry.json lists files)──►  pnpm registry:build (shadcn build)
                                                                 │
                                                                 ▼
                                               public/r/<base>/<name>.json  ──►  npx shadcn add @pdfcn/<base>/<name>
examples/<base>/<name>.tsx ──► examples/__index__.ts ──► app/api/pdf/<base>/route.tsx ──► <ComponentPreview> in MDX docs
```

- The docs preview and the published registry read the same source files, so a preview that
  renders correctly is strong evidence the installed item will too.
- `<ComponentSource src="registry/...">` in MDX shows the live source file, so docs never embed
  copied code for the manual-install tab.
- `components/web-mcp/pdf-tool.tsx` exposes a WebMCP tool that opens a block's PDF; its
  `BLOCK_NAMES` array must list every block.
